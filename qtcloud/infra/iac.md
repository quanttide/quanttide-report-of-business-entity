# 基础设施编排

发现 Flash 在 Opencode 里过度思考、迷失方向 这个表象问题，一路追问，最终找到了根本解：

1. 问题根因不是 Opencode，而是轻量模型面对基础设施场景的复杂依赖时，能力不够+透明度引导放大了混乱。
2. 无法单靠模型或框架解决，必须从方法论和工具链入手。
3. 方法论核心：意图 → 状态机 → 代码生成，把推理和翻译彻底分离。
4. 落地方式：每个模块 先写 .md 意图声明，再生成 .tf 代码，同级、同名、一一对应。

现在你有了一个清晰的、可执行的结构：

```
modules/
├── postgresql/
│   ├── pg.md          ← 你先写这个
│   ├── pg.tf          ← 由 md 生成
│   ├── variables.tf
│   └── outputs.tf
└── stack-auth/
    ├── stack-auth.md
    ├── stack-auth.tf
    ├── variables.tf
    └── outputs.tf
```

这个结构彻底消灭了“AI 把问题搞复杂然后迷失”的空间，因为 AI 不再需要猜你的意图，它只做“严格的翻译”。
